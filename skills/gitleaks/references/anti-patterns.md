## Anti-patterns

- **Don't pass `--no-git` to `dir`.** `--no-git` belongs to the deprecated `detect` command (`gitleaks detect --source <path> --no-git`), **not** to `dir`. At 8.30.1 `gitleaks dir <target> --no-git` fails with `Error: unknown flag: --no-git` and exit **126**. The host-side wrapper in `harness/tools/sast.py` (`gitleaks detect --source ... --no-git -v`) runs on the host and must not be copied into the container; in-container, `gitleaks dir <target>` is the no-git scan.
- **Don't rely on `git` for a tree without `.git`.** `gitleaks git` pointed at a non-repo logs `fatal: not a git repository`, reports `0 commits scanned`, and exits **0** — a false clean that looks like a pass. Check for `.git` first; when it is absent use `dir`.
- **Don't scan only with `--staged` and call it a day.** `--staged` cannot see history; a leak that landed before the hook existed is invisible until you run `gitleaks git` over the repo. A one-off `--staged` result is a diff check, not an audit.
- **Don't use `gitleaks detect` / `gitleaks protect` on new code.** Both are deprecated since v8.19.0 (still functional at this pin but hidden in `--help`, and their flags are not shared with `dir`/`git`). Use `gitleaks dir` for a tree and `gitleaks git` for history.
- **Don't** silently `--redact` everywhere. Reports and logs benefit from redaction, but when you are remediating you need the literal value to grep, rotate, and confirm. Run unredacted only where the output stays in a scratch file under `$HOME`.
- **Don't** allowlist by full secret value. `regexes = ['''ghp_aBcD…the actual key''']` becomes wrong the moment someone rotates the key — and rotations are exactly when you cannot afford a noisy false negative. Allowlist by **shape** (path, rule id, fixture-prefix regex), not literal value.
- **Don't** assume "leak found" = "leak in HEAD". Git history is forever. Removing the line in a new commit does **not** purge the blob — you need `git-filter-repo` (or BFG), force-push, then **rotate the credential** because anyone who cloned still has it.
- **Don't** ignore exit code 1 with `|| true` to make a run green. That is the entire point of the tool. If the finding is a fixture, allowlist it; if it is real, rotate and remediate.
- **Don't** read exit 0 as proof of cleanliness. Exit 0 also covers the silent git-on-non-repo path, and a rule that does not know an internal token format will never match it. Confirm the report is empty and stderr has no `ERR`/`FTL`, then treat absence as "no rule fired", not "no secret".
- **Don't** treat low-entropy strings as automatically safe. Many real keys have structure, not randomness — `AKIA…` (AWS access key) is 20 chars of base32 with a fixed prefix, not high-entropy noise. Keyword + regex matters as much as Shannon entropy.
- **Don't** write `--report-path` into the target. The mount is read-only: gitleaks fails with `Report path is not writable` and exit 1. Reports, baselines, and generated configs go under `$HOME`.
